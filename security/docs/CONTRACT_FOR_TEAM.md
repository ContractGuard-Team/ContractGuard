# Interface freeze for AI, SE, ATTT

## AI → C# exchange
1. Python worker emits `schemas/extraction.schema.json`-compliant JSON, with immutable `job_id`, `tenant_id`, `contract_id`, and `contract_version` supplied via authenticated job metadata. These fields MUST NOT be trusted if generated by an LLM.
2. Each `facts` entry references a clause ID, original page and quote. Quote is *claim of source evidence* and MUST be independently checked against canonical parsed text/page anchors by the ingestion/evidence pipeline.
3. `document_complete=false` means negative findings from absence cannot be auto-concluded.
4. C# performs final policy application/scoring, tenant authorization, jobs state transition, DB writes, versioning, and result idempotency.
5. Python in `src/rule_validator.py` is an **offline reference checker**, NOT production risk service. SE must implement exact semantics or execute a shared conformance suite.
6. Final validated results use `schemas/security-findings.schema.json`; include `policy_version`, `rule_set_version`, contract version, extraction/model/prompt versions and source hash in production audit metadata.
7. `tenant_id` in message is a consistency field only: verify it from canonical job data owned by backend, not from untrusted model/message alone.
8. A missing clause is `NEEDS_REVIEW`, not automatically illegal or `FAIL`; confirmed policy violations differ from violations of law. Jurisdiction and side (buyer/seller) are required before providing legal conclusions.

- [ ] ATTT approves rule semantics/context
- [ ] Test fixture regression test passes for SE and ATTT implementations
